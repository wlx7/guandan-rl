# 训练说明

## 用同一副牌比较两种出法

普通自对弈只记录实际打出去的那手牌。成对微调会从基准模型的自对弈中抽取决策点，复制当时的整副牌，让首选动作和另一个分数接近的合法动作各走一遍。之后四个座位都按基准模型打到终局。训练标签是两条分支从出牌方看得到的级差之差。相同的底牌和后续策略使比较更容易；模型出牌时看到的仍然只有自己的手牌和公开记录。

下面的命令从一份已有权重开始训练。只更新动作评分部分，保留状态编码和手牌预测头。每 16 轮保存一个候选权重，最后一轮也保存。输出目录应单独命名。

```bash
python -m guandan.train_pairs base.pt candidates/level --iterations 192
python -m guandan.train_pairs base.pt candidates/win --initial-head candidates/level/pair-80.pt --win-weight 0.75 --iterations 48 --seed 29013 --deal-seed 281000
```

第一条命令以升降级为目标。第二条命令从第一阶段的评分头继续，把目标改为 75% 的单局胜负和 25% 的升降级。两组都使用同一份 `base.pt` 负责后续出牌。训练从随机级牌的单局开始，未覆盖进还贡决策。

用复式牌筛选候选，选定后换一个从未参与筛选的种子做验收。例如下面这条命令会打 20,000 局。统计单位是同一副牌的两次换边结果，命令输出的误差为一个标准误。

```bash
python -m guandan.evaluate candidates/level/pair-80.pt --opponent base.pt --deals 10000 --batch 128 --device cuda --seed 90821
```

## 算法：深度蒙特卡洛（DMC）纯自对弈

本项目不使用任何人类对局数据或手写策略来训练，AI 完全通过和自己打牌学会掼蛋：

1. 多个**自对弈进程**同时运行上百局比赛，四个座位都由当前最新的网络来出牌（以概率 ε 随机探索）。
2. 每个决策点记录三样东西：当时能看到的局面（自己的手牌 + 公开的出牌历史）、选择的那手牌、以及这一局最后的结果（本方升了几级或被对方升了几级）。
3. **学习进程**用这些样本训练 Q 网络：让 Q(局面, 出牌) 去拟合这一局实际的结果。
4. 出牌时，AI 对所有合法出牌计算 Q 值，选最大的那一手。

这就是 DouZero（斗地主）和 DanZero（掼蛋）采用的方法。它简单、稳定，而且很适合动作空间巨大的扑克游戏：模型对每个候选出牌单独打分，不需要固定的动作表。

还贡也是一个由网络决策的动作（候选为所有 10 或以下的牌），因此进贡体系对出牌的影响也会被学到。

### 每个 AI 只能看到公开信息

特征全部从当前玩家的视角编码（[`src/features.rs`](../src/features.rs)）：

- 自己的手牌（带花色，108 维）和按大小排列的点数计数
- 其他三家**已经打出的牌**、尚未出现的牌（=自己手牌和已出牌之外的所有牌）
- 三家剩余张数、名次、本局级牌和双方级数、庄家
- 当前要压的牌、谁出的、连续不要的次数
- 进贡 / 还贡记录（公开信息）
- 最近 24 手出牌的序列（送入 LSTM）

候选出牌的特征包括：这手牌本身、牌型、大小、用了几张逢人配、出完后剩余手牌、是否拆了炸弹等。

### 网络结构

```
历史 24 手 ──LSTM──┐
                   ├─ 状态 MLP ──┐
局面特征 1550 维 ──┘             ├─ 打分 MLP ── Q 值
候选出牌特征 413 维 ─────────────┘
```

状态编码每个决策只算一次，然后与所有候选出牌拼接后一次性打分，因此一次前向就能评估几十局里的所有候选出牌。

### 模型大小

| 预设 | 参数量 | fp16 体积 | 建议 |
|---|---|---|---|
| tiny | 0.58M | 1.2 MB | 调试用 |
| small | 1.23M | 2.5 MB | 只有 CPU 时 |
| **medium** | **2.46M** | **4.9 MB** | **推荐** |
| large | 5.52M | 11 MB | GPU、长时间训练；v1.10 起的随包模型 |
| xlarge | 8.60M | 17.2 MB | 实验用 |

**在小模型基础上练大模型**：选了基准模型时再选更大的尺寸（命令行 `--base 模型.pt --preset large`），程序会先把基准模型“加宽”（Net2Net：每层复制已有的神经元，把它们的输出权重随机拆分，函数保持不变；多出的层设成直通），开局打法和原模型完全一样，再继续自对弈。这样大模型不用花几十小时从零追上小模型，直接从小模型的水平出发利用多出的容量。

**v1.10 实测：加宽 + 长时间训练 + 快照平均。** 把 v1.9.0 的 medium 加宽成 large 后，在 RTX 5090 上自对弈 37 亿样本（约 8.5 小时），最后 4 个快照取平均，对 v1.9.0 每局多赢 0.344 级（3 万副新牌）。medium 早已停滞，large 在 37 亿样本时还在上涨；xlarge 在相同样本量下与 large 持平。详见[随包模型说明](MODEL.md)。

从零开始训练时仍推荐 medium：样本少时它学得最快。

为什么推荐 medium：掼蛋的局面信息量（两副牌、逢人配、四人历史）比斗地主大，tiny/small 在长时间训练后会明显欠拟合；而 large 以上需要成倍的样本量才能训练充分，在单卡、几十小时的训练预算下胜率提升很小，体积和推理延迟却翻倍。medium 是“用最小体积获得接近饱和能力”的折中点。发布的模型以 fp16 保存，约 5 MB。

## 训练到底有没有停滞？

v1.1 时我们以为训练在 300 万样本后就停在了“对规则 AI 胜率 60%”。后来改用**复式评估**（每副牌打两遍、交换座位、用固定的一批牌、几千局）重新测量，发现并不是：

| 模型 | 累计训练样本 | 对规则 AI（每局升级数） | 每局胜率 |
|---|---|---|---|
| v1.1 随包模型 | 0.55 亿 | +0.53 ± 0.05 | 60.7% |
| 继续训练 | 1.06 亿 | +0.51 ± 0.05 | 60.2% |
| 再练 2 小时（v1.3 随包） | 3.14 亿 | +1.19 ± 0.04 | 71.5% |
| 再练 3 小时（v1.4.1 随包） | 6.56 亿 | +1.61 ± 0.03 | 78.8% |
| 再练 2 小时 + 预测手牌辅助任务（v1.5.1 随包） | 8.84 亿 | +1.91 ± 0.04 | 83.7% |
| 再练 2.75 小时，辅助任务权重 1.0（v1.6.1 随包） | 12.1 亿 | +2.09 ± 0.02 | 87.5% |
| **自动调参再练 4.5 小时：批大小 4096、学习率 5e-5（v1.6.2 随包）** | **17.7 亿** | **+2.25 ± 0.02** | **89.1%** |

（1000～2000 副牌复式对局；v1.4.1 模型直接对 v1.1 随包模型 +1.33 级/局，胜率 73%；对 v1.3 +0.58 级/局，胜率 61%；v1.6.1 模型直接对 v1.5.1/v1.6.0 随包模型 +0.35 级/局，胜率 56.7%；v1.6.2 模型直接对 v1.6.1 模型 +0.28 级/局，胜率 54.9%。）

以前的评估每次只打 400 局普通对局，误差有 ±0.2 级/局，正好把这种逐步的进步淹没了；而 0.55 亿到 1.06 亿之间只练了半小时，本来也看不出差别。纯自对弈 DMC 只要继续训练就会继续变强。

为了理解训练的难点，我们还做了几组测量：

| 测量 | 结果 | 说明 |
|---|---|---|
| 同一副牌、交换座位后，0 号队两次结果的相关系数 | 网络 vs 规则 AI 0.10；两个网络之间 0.30 | 牌好牌坏只决定一小部分输赢，打法影响极大，局势对每一步出牌都很敏感 |
| 自对弈时随机探索（ε=0.02）造成的结果方差 | 约占总方差 30% | 一步随机出牌就能改变整局结果，训练目标噪声大，需要大量样本 |
| 能看到四家手牌的“完全信息价值网络”比普通价值网络多解释的方差 | 约 7% | 即使知道所有手牌，结果也很难预测，用它做基线降噪收益很小，没有采用 |

## 对手池训练（可选，默认关闭）

`--league 0.5` 会让一半对局的对手由早先版本的模型来打（基准模型、`--pool` 指定的模型和本次训练的快照），只用最新模型自己的出牌做样本，想法是避免网络只学会“打自己”。

2+2 小时的对比实验（RTX 3060 笔记本，都从 1.06 亿样本的模型出发，2000 副牌复式评估）：

| 训练 2 小时 | 样本数 | 对规则 AI | 对起点模型 |
|---|---|---|---|
| 纯自对弈（ε=0.02） | 2.08 亿 | **+1.18**，胜率 71.9% | **+0.83** |
| 对手池（ε=0.01） | 1.12 亿 | +0.84，胜率 65.4% | +0.50 |

两者直接对打，纯自对弈每局多赢 0.34 级。对手池每一步要多跑一个网络、一半对局只有两个座位产生样本，同样时间里样本只有一半，这个代价超过了它的好处。因此默认仍是纯自对弈。

## 推演搜索（AI 深度思考）

对战时可以选择**推演搜索**（`python/guandan/search.py`，v1.5 起默认关闭，见下文），整个过程不使用任何人工规则：

1. 网络给所有合法出牌打分，取最好的 5 手作为候选。
2. 根据当前玩家能看到的信息（已出的牌、每家剩余张数、进贡还贡记录）随机推测另外三家的手牌，采样 24 个“可能的世界”（Rust 实现，`Game::determinize`）。
3. 在每个世界里打出候选牌，然后四家都由网络接着往下打 14 步，再用网络估计局面价值（若本局已结束就用真实结果）。所有世界、所有候选一起批量推理。
4. 取各候选在所有世界里的平均结果，最高的就是 AI 的出牌。

在 1.06 亿样本的较弱模型上，搜索很有用（对规则 AI，同一批 320 副牌、640 局复式对局）：

| 出牌方式 | 每局升级数 | 每局胜率 |
|---|---|---|
| 只用网络 | +0.50 ± 0.08 | 61.1% |
| 搜索，12 个世界 | +0.71 ± 0.08 | 64.1% |
| 搜索，24 个世界 | +0.93 ± 0.08 | 68.8% |
| 搜索，12 个世界，推演 30 步 | 约 +0.7（256 副牌） | 63% |
| 搜索，推演时网络随机出牌 | +0.36 ± 0.09 | 57.7% |

但网络练强以后，情况反过来了（v1.4.1 随包模型，同一批 400 副牌、800 局）：

| 出牌方式 | 对规则 AI | 每局胜率 |
|---|---|---|
| **只用网络** | **+1.52 ± 0.06** | **77.0%** |
| 搜索，12 个世界 | +1.11 ± 0.07 | 70.9% |
| 搜索，24 个世界 | +1.27 ± 0.07 | 74.8% |
| 搜索，48 个世界 | +1.45 ± 0.07 | 77.0% |

搜索版和网络直接对打也输 0.18 ± 0.06 级/局。

v1.6 又试了两处改进（v1.5.1 随包模型，和只用网络的自己直接对打，160 副牌）：

| 搜索方式 | 对只用网络 |
|---|---|
| 平均推测手牌，取平均结果最好的一手（原做法） | 约 −0.7（前 32 副牌） |
| 平均推测手牌，只有显著更好（超过 2 倍误差）才推翻网络的选择 | −0.48 ± 0.10 |
| **按网络学到的手牌预测采样**，只有显著更好才推翻 | −0.18 ± 0.10 |

一局牌对每一步都很敏感，24 个推测世界的估计误差约 ±0.4 级，而强网络前几个候选之间的真实差距远小于这个误差，所以原做法几乎是在噪声里挑；加上“显著才推翻”和按预测采样后好了很多，但仍不如网络本身。原因在于随机推测手牌时用的是“所有没出现的牌平均分配”，丢掉了网络从对手出牌里学到的推断；网络弱的时候推演的收益更大，网络强了以后这部分损失就占了上风。所以从 v1.5 起对战默认只用网络，推演搜索保留为“实验”选项。

**没有采用的尝试：按出牌推断手牌。** 让网络评估“在这个推测的世界里，对手刚才那几手牌出得有多合理”，按这个概率给世界加权。自对弈时这样推测出的手牌和真实手牌的重合度从 51% 提高到 58%，但对规则 AI 反而明显变差：规则 AI 的打法和网络不同（例如从不压队友），用网络的眼光去解读它的出牌会推错。默认关闭（`SearchAgent(belief=...)`）。

搜索前后的对比可以用命令行测：`python -m guandan.evaluate model.pt --opponent rule --search 5,24,14`。

## 辅助任务：预测其他三家的手牌（v1.5 起默认开启）

`--aux`（默认 1.0，v1.5～v1.6 为 0.25）给网络加一个只在训练时使用的输出头：根据当前局面编码，预测其他三家手里各有哪些牌。训练时真实手牌是已知的，这样每个样本除了一个噪声很大的胜负结果，还多了 324 位的监督信号，迫使网络的局面表示学会记牌和推断手牌。思路来自开源的 [DanLM](https://github.com/dashidhy/DanLM)（用“预测下一手出牌”做辅助任务）和 [DanKS](https://github.com/Calix-L/DanKS)（队友信念辅助分支）。对战时这个输出头不参与决策，AI 仍然只看公开信息。

对比实验（RTX 3060 笔记本，都从 v1.4.1 随包模型出发各练 2 小时，样本量相同，2000 副牌复式评估）：

| 训练 2 小时 | 对规则 AI | 对起点模型 |
|---|---|---|
| 普通 DMC | +1.70 ± 0.03，胜率 80.4% | +0.07 ± 0.03 |
| **DMC + 预测手牌（aux 0.25）** | **+1.89 ± 0.03，胜率 83.2%** | **+0.51 ± 0.03** |

两者直接对打，加了辅助任务的模型每局多赢 **0.39 ± 0.03 级**（胜率 57.4%）。速度几乎不变（每秒约 3.2 万样本），模型多 17 万参数（文件约 5.3 MB）。

辅助任务的权重也值得调大。从 v1.5.1 随包模型出发各练 1.5 小时（2000 副牌复式评估）：

| 继续训练 1.5 小时 | 对规则 AI | 对起点模型（v1.5.1） |
|---|---|---|
| aux 0.25 | +1.98 ± 0.03，胜率 86.3% | +0.09 ± 0.03 |
| **aux 1.0** | **+2.07 ± 0.02，胜率 86.4%** | **+0.25 ± 0.03** |

直接对打 aux 1.0 每局多赢 **0.15 ± 0.03 级**，所以从 v1.6.1 起默认权重改为 1.0。

## 自动调参实验（爬山法）

为了找出还能提高的训练设置，我们在 RTX 3060 笔记本上按轮做对照实验：每一轮从当前最好的模型出发，几组设置各练同样长的时间，然后用 2000 副牌复式对局和对照组（设置不变的那组）直接对打；只有赢对照组超过 2 个标准误差的设置才会被采用，否则保留对照组继续下一轮。

| 轮次 | 设置（aux 1.0；第 1 轮从 w100 出发各练 1.25 小时，之后每轮从上一轮的胜者出发各练 1.5 小时） | 对规则 AI | 对对照组 |
|---|---|---|---|
| 第 1 轮 | **对照组（不变）** | **+2.11 ± 0.02，胜率 87.6%** | — |
| | 加“预测下一手”辅助任务（`--ntp 0.25`） | +2.22 ± 0.02，胜率 88.0% | −0.03 ± 0.03 |
| | 学习率 1e-4（默认 2e-4） | +2.04 ± 0.02，胜率 86.8% | +0.04 ± 0.03（不显著） |
| 第 2 轮 | **对照组（不变）** | **+2.20 ± 0.02，胜率 88.3%** | — |
| | 探索率 0.01（默认 0.02） | +2.15 ± 0.02，胜率 88.2% | +0.03 ± 0.03（不显著） |
| | 辅助任务权重 2.0 | +2.20 ± 0.02，胜率 88.1% | −0.00 ± 0.03 |
| 第 3 轮 | 对照组（不变） | +2.19 ± 0.02，胜率 88.6% | — |
| | **批大小 4096（GPU 默认 2048）** | **+2.20 ± 0.02，胜率 88.7%** | **+0.10 ± 0.03** |
| | 每个样本平均训练 2 次（`--reuse 2`） | +1.89 ± 0.03，胜率 84.1% | −0.39 ± 0.03 |
| 第 4 轮 | 对照组（批大小 4096，学习率 2e-4） | +2.23 ± 0.02，胜率 88.7% | — |
| | 学习率 1e-4 | +2.26 ± 0.02，胜率 89.3% | +0.09 ± 0.02 |
| | **学习率 5e-5** | **+2.26 ± 0.02，胜率 89.6%** | **+0.10 ± 0.02** |

第 1 轮两种改动都没有明显胜过对照组。“预测下一手”对规则 AI 的成绩更好，但两个模型直接对打时并不占优，说明它只是更会赢规则 AI 的套路，没有整体变强；降低学习率略有优势但在误差范围内，后面会在更晚的阶段再测一次。

第 2 轮也没有改动胜出：探索率减半略有优势但不显著，辅助任务权重从 1.0 加到 2.0 没有区别。值得注意的是，第 2 轮对照组（比 v1.6.1 随包模型多练 1.5 小时）直接对 v1.6.1 模型只多赢 **0.02 ± 0.03 级**，而前面每练 1.5 小时还能多赢 0.1～0.25 级——按现在的学习率继续练，进步明显放缓了。下一步重点试降低学习率（第 4 轮）。

第 3 轮找到了第一个有效的改动：**批大小从 2048 加到 4096**，直接对打每局多赢 0.10 ± 0.03 级（约 4 个标准误差）。这个模型对 v1.6.1 随包模型每局多赢 0.16 ± 0.03 级。反过来，让每个样本多训练一次（`--reuse 2`）明显变差（−0.39 级）：自对弈的样本很快就过时了，反复用旧样本训练有害。

第 4 轮两种更小的学习率都明显胜过对照组（各约 4 个标准误差），说明模型练强以后需要更小的步长来细调，这也解释了第 2 轮的停滞。学习率 5e-5 的模型对 v1.6.1 随包模型每局多赢 **0.28 ± 0.03 级**，对第 3 轮的胜者多赢 0.08 ± 0.03 级，成为 v1.6.2 的随包模型。从 v1.6.2 起，在已有模型上继续训练默认使用 5e-5，显卡训练默认批大小 4096。

### 云端几轮（AutoDL，A800 + 14 核 CPU）

云主机每秒约 9.8 万样本，是 RTX 3060 笔记本的 2.9 倍；瓶颈在 CPU（自对弈进程开到 6 个以后不再变快，学习进程只有约 40% 的时间在忙）。每组练 1 小时，约等于笔记本 3 小时。

| 轮次 | 设置（都从 v1.6.3 模型再练 25 分钟的版本出发） | 对规则 AI | 对对照组 |
|---|---|---|---|
| 云端第 1 轮 | 对照组（批大小 4096，学习率 5e-5） | +2.24 ± 0.02，胜率 89.5% | — |
| | 学习率 2.5e-5 | +2.30 ± 0.02，胜率 89.6% | +0.04 ± 0.02（不显著） |
| | 每个自对弈进程同时 512 局 | +2.30 ± 0.02，胜率 90.0% | +0.03 ± 0.02（不显著） |

更重要的是：对照组又练了约 1.4 小时（相当于笔记本 4 小时、约 5 亿样本），直接对 v1.6.3 模型却是 **−0.02 ± 0.02 级**，没有可测的进步。按现在的设置，medium 模型已经练到平台期，继续堆训练时间收益很小；下一步要么继续降低训练噪声（更大的批、更小的学习率），要么换更大的模型。

云端第 2 轮（批大小 8192、探索率 0.01）开始半小时后停止：预计提升很小，不值得继续付费。目前最强的仍是 v1.6.2/v1.6.3 随包模型。

### 实验：搜索标注训练（专家迭代）

`--search-actors N` 会额外启动 N 个进程：它们用推演搜索打牌，并把每个决策里网络前几名候选的**搜索值**（多个可能世界里推演结果的平均）作为训练目标，与普通样本按 `--search-share` 的比例混合训练。搜索值比单局结果的噪声小得多，而且正好覆盖网络最需要区分的那几手。这个选项默认关闭，效果还在评估中。

## 评估：怎样看胜率曲线

训练中会定期把最新模型拿出来，用**复式对局**和三个对手比较：每副牌打两遍，第二遍双方交换座位，牌运基本抵消；每次评估都用同一批牌，前后两次评估的差别就是模型本身的变化。

- **对规则 AI**：一个手写的简单策略（先出小牌、不拆炸弹、不压队友、对手快出完时才炸）。它从不参与训练，只作为一把固定的尺子。
- **对基准模型**：如果选了基准模型，比较新模型是否超过了它。
- **对随机出牌**：最早期的进展。

胜率按局计算：头游在哪一方，哪一方赢下这一局。另一条曲线是平均每局升级数（赢 +1/+2/+3，输则为负），比单纯胜率更能体现“打得漂不漂亮”，评估记录里同时给出它的标准误（±）。

## 推荐参数

参数默认都是“自动”，一般不用改：

| 机器 | 自对弈 | 每进程对局 | 批大小 | 说明 |
|---|---|---|---|---|
| 有 NVIDIA 显卡 | GPU，3 个进程 | 256 | 4096 | 自对弈和学习都在显卡上；RTX 3060 笔记本实测单个 GPU 自对弈进程约 3 万次决策/秒 |
| 只有 CPU | CPU，线程数减 2～4 个进程 | 64 | 512 | 每个进程单线程；选 small 或 medium |

- 有显卡时，自对弈也放在 GPU 上：每个进程同时跑 256 局，一次前向给所有对局打分，比 CPU 多进程快得多，也不会和学习进程抢 CPU。
- 训练中心的日志里 `learner=xx%` 表示学习进程的忙碌程度：接近 100% 说明学习跟不上（可减少自对弈进程），很低说明瓶颈在自对弈（可增加进程数或每进程对局数）。
- 学习率默认自动：从头训练用 2e-4；选了基准模型、在已有模型上继续训练时用 5e-5（自动调参第 4 轮实测，继续训练强模型时小学习率每局多赢约 0.1 级）。
- 训练可以随时停止。用**同一个名称**再次开始就会从上次的进度继续（包括优化器状态）。
- 一般几百万样本后就能稳定战胜规则 AI；样本越多越强（随包模型训练了约 17.7 亿样本、约 15 小时，仍在进步），建议至少训练几个小时。

## 在云主机上训练

笔记本跑不动时，可以按小时租一台 Linux GPU 云主机（AutoDL、恒源云等）。这个模型很小，瓶颈主要在 CPU 上的牌局模拟，所以选 **RTX 4090 这类单卡、每卡 CPU 核数尽量多（12 核以上）** 的机器即可，不需要 A100。镜像选带 PyTorch 2.x、CUDA 12 的 Ubuntu 镜像。

在云主机的终端里运行（AutoDL 先 `source /etc/network_turbo` 加速 GitHub）：

```bash
curl -fsSLO https://raw.githubusercontent.com/wlx7/guandan-rl/main/scripts/cloud_train.sh
bash cloud_train.sh bench        # 约 10 分钟：测几种并行设置的速度，和 RTX 3060 笔记本（约 3.4 万样本/秒）对比
bash cloud_train.sh train 10     # 后台训练 10 小时（从内置模型继续），关掉网页也不会停
bash cloud_train.sh status       # 查看进度和评估结果
bash cloud_train.sh pack         # 把模型复制到 export/，在网页文件浏览器里下载
```

下载的模型放进本机 `guandan_data/models/`，开桌时就能在“模型库”里选它。想从别的模型继续，运行前设置 `BASE=/路径/model.pt`。

## 命令行训练

```bash
python -m guandan.train --name main --preset medium        # 其余参数自动选择（默认 --aux 1.0）
# 从已有模型继续：
python -m guandan.train --name finetune --base path/to/model.pt
# 对手池（实验，默认关闭），再加几个老模型（用分号分隔）：
python -m guandan.train --name league --base new.pt --league 0.5 --pool "old1.pt;old2.pt"
# 停止：在 guandan_data/runs/<name>/ 下创建名为 STOP 的空文件，或按 Ctrl+C
```

评估两个模型：

```bash
python -m guandan.evaluate guandan_data/runs/main/model.pt --opponent rule --deals 1000
python -m guandan.evaluate new.pt --opponent old.pt --deals 1000
python -m guandan.evaluate new.pt --opponent rule --search 5,24,14 --deals 300   # 开启推演搜索
```

## 训练产物

`guandan_data/runs/<name>/` 下：

- `ckpt_latest.pt`：完整检查点（含优化器，用于继续训练）
- `model.pt`：最新模型（fp16，用于对战）
- `model_<样本数>k.pt`：每小时保存一次的快照
- `metrics.jsonl`：训练与评估记录（训练中心的曲线就来自这里）
- `train.log`：训练日志
