# 训练说明

## 算法：深度蒙特卡洛（DMC）纯自对弈

本项目不使用任何人类对局数据或手写策略来训练，AI 完全通过和自己打牌学会掼蛋：

1. 多个**自对弈进程**同时运行上百局比赛，四个座位都由当前最新的网络来出牌（以概率 ε 随机探索）。
2. 每个决策点记录三样东西：当时能看到的局面（自己的手牌 + 公开的出牌历史）、选择的那手牌、以及这一局最后的结果（本方升了几级或被对方升了几级）。
3. **学习进程**用这些样本训练 Q 网络：让 Q(局面, 出牌) 去拟合这一局实际的结果。
4. 出牌时，AI 对所有合法出牌计算 Q 值，选最大的那一手。

这就是 DouZero（斗地主）和 DanZero（掼蛋）采用的方法。它简单、稳定，而且很适合动作空间巨大的扑克游戏：模型对每个候选出牌单独打分，不需要固定的动作表。

还贡也是一个由网络决策的动作（候选为所有 10 或以下的牌），因此进贡体系对出牌的影响也会被学到。

### 每个 AI 只能看到公开信息

特征全部从当前玩家的视角编码（[`src/features.rs`](../src/features.rs)）：

- 自己的手牌（带花色，108 维）和按大小排列的点数计数
- 其他三家**已经打出的牌**、尚未出现的牌（=自己手牌和已出牌之外的所有牌）
- 三家剩余张数、名次、本局级牌和双方级数、庄家
- 当前要压的牌、谁出的、连续不要的次数
- 进贡 / 还贡记录（公开信息）
- 最近 24 手出牌的序列（送入 LSTM）

候选出牌的特征包括：这手牌本身、牌型、大小、用了几张逢人配、出完后剩余手牌、是否拆了炸弹等。

### 网络结构

```
历史 24 手 ──LSTM──┐
                   ├─ 状态 MLP ──┐
局面特征 1550 维 ──┘             ├─ 打分 MLP ── Q 值
候选出牌特征 413 维 ─────────────┘
```

状态编码每个决策只算一次，然后与所有候选出牌拼接后一次性打分，因此一次前向就能评估几十局里的所有候选出牌。

### 模型大小

| 预设 | 参数量 | fp16 体积 | 建议 |
|---|---|---|---|
| tiny | 0.58M | 1.2 MB | 调试用 |
| small | 1.23M | 2.5 MB | 只有 CPU 时 |
| **medium** | **2.46M** | **4.9 MB** | **推荐** |
| large | 5.27M | 10.5 MB | GPU、长时间训练 |
| xlarge | 8.60M | 17.2 MB | 实验用 |

为什么推荐 medium：掼蛋的局面信息量（两副牌、逢人配、四人历史）比斗地主大，tiny/small 在长时间训练后会明显欠拟合；而 large 以上需要成倍的样本量才能训练充分，在单卡、几十小时的训练预算下胜率提升很小，体积和推理延迟却翻倍。medium 是“用最小体积获得接近饱和能力”的折中点。发布的模型以 fp16 保存，约 5 MB。

## 评估：怎样看胜率曲线

训练中会定期把最新模型拿出来，和三个对手各打数百局：

- **对规则 AI**：一个手写的简单策略（先出小牌、不拆炸弹、不压队友、对手快出完时才炸）。它从不参与训练，只作为一把固定的尺子。
- **对基准模型**：如果选了基准模型，比较新模型是否超过了它。
- **对随机出牌**：最早期的进展。

胜率按局计算：头游在哪一方，哪一方赢下这一局。另一条曲线是平均每局升级数（赢 +1/+2/+3，输则为负），比单纯胜率更能体现“打得漂不漂亮”。两条曲线都会有随机波动（400 局的标准误约 ±2.5%），看趋势即可。

## 推荐参数

| 机器 | 自对弈进程数 | 每进程对局 | 批大小 | 说明 |
|---|---|---|---|---|
| 8 核 CPU，无 GPU | 6 | 64 | 512 | 选 small 或 medium |
| 12–20 线程 CPU + RTX 3060 | 12–16 | 64 | 1024 | medium，约 3–5 万样本/秒 |
| 更多核 + 高端 GPU | 24+ | 64 | 2048 | 可以考虑 large |

- 自对弈默认在 CPU 上跑（每个进程一个线程），GPU 留给学习进程；这在大多数机器上最快。
- 训练可以随时停止。用**同一个名称**再次开始就会从上次的进度继续（包括优化器状态）。
- 一般几百万样本后就能稳定战胜规则 AI；要打出高水平需要数亿样本（RTX 3060 笔记本上约一两天）。

## 命令行训练

```bash
python -m guandan.train --name main --preset medium --actors 12 --envs 64 --batch 1024
# 从已有模型继续：
python -m guandan.train --name finetune --base path/to/model.pt
# 停止：在 guandan_data/runs/<name>/ 下创建名为 STOP 的空文件，或按 Ctrl+C
```

评估两个模型：

```bash
python -m guandan.evaluate guandan_data/runs/main/model.pt --opponent rule --rounds 2000
python -m guandan.evaluate new.pt --opponent old.pt
```

## 训练产物

`guandan_data/runs/<name>/` 下：

- `ckpt_latest.pt`：完整检查点（含优化器，用于继续训练）
- `model.pt`：最新模型（fp16，用于对战）
- `model_<样本数>k.pt`：每小时保存一次的快照
- `metrics.jsonl`：训练与评估记录（训练中心的曲线就来自这里）
- `train.log`：训练日志
