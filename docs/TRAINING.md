# 训练说明

## 算法：深度蒙特卡洛（DMC）纯自对弈

本项目不使用任何人类对局数据或手写策略来训练，AI 完全通过和自己打牌学会掼蛋：

1. 多个**自对弈进程**同时运行上百局比赛，四个座位都由当前最新的网络来出牌（以概率 ε 随机探索）。
2. 每个决策点记录三样东西：当时能看到的局面（自己的手牌 + 公开的出牌历史）、选择的那手牌、以及这一局最后的结果（本方升了几级或被对方升了几级）。
3. **学习进程**用这些样本训练 Q 网络：让 Q(局面, 出牌) 去拟合这一局实际的结果。
4. 出牌时，AI 对所有合法出牌计算 Q 值，选最大的那一手。

这就是 DouZero（斗地主）和 DanZero（掼蛋）采用的方法。它简单、稳定，而且很适合动作空间巨大的扑克游戏：模型对每个候选出牌单独打分，不需要固定的动作表。

还贡也是一个由网络决策的动作（候选为所有 10 或以下的牌），因此进贡体系对出牌的影响也会被学到。

### 每个 AI 只能看到公开信息

特征全部从当前玩家的视角编码（[`src/features.rs`](../src/features.rs)）：

- 自己的手牌（带花色，108 维）和按大小排列的点数计数
- 其他三家**已经打出的牌**、尚未出现的牌（=自己手牌和已出牌之外的所有牌）
- 三家剩余张数、名次、本局级牌和双方级数、庄家
- 当前要压的牌、谁出的、连续不要的次数
- 进贡 / 还贡记录（公开信息）
- 最近 24 手出牌的序列（送入 LSTM）

候选出牌的特征包括：这手牌本身、牌型、大小、用了几张逢人配、出完后剩余手牌、是否拆了炸弹等。

### 网络结构

```
历史 24 手 ──LSTM──┐
                   ├─ 状态 MLP ──┐
局面特征 1550 维 ──┘             ├─ 打分 MLP ── Q 值
候选出牌特征 413 维 ─────────────┘
```

状态编码每个决策只算一次，然后与所有候选出牌拼接后一次性打分，因此一次前向就能评估几十局里的所有候选出牌。

### 模型大小

| 预设 | 参数量 | fp16 体积 | 建议 |
|---|---|---|---|
| tiny | 0.58M | 1.2 MB | 调试用 |
| small | 1.23M | 2.5 MB | 只有 CPU 时 |
| **medium** | **2.46M** | **4.9 MB** | **推荐** |
| large | 5.27M | 10.5 MB | GPU、长时间训练 |
| xlarge | 8.60M | 17.2 MB | 实验用 |

为什么推荐 medium：掼蛋的局面信息量（两副牌、逢人配、四人历史）比斗地主大，tiny/small 在长时间训练后会明显欠拟合；而 large 以上需要成倍的样本量才能训练充分，在单卡、几十小时的训练预算下胜率提升很小，体积和推理延迟却翻倍。medium 是“用最小体积获得接近饱和能力”的折中点。发布的模型以 fp16 保存，约 5 MB。

## 训练到底有没有停滞？

v1.1 时我们以为训练在 300 万样本后就停在了“对规则 AI 胜率 60%”。后来改用**复式评估**（每副牌打两遍、交换座位、用固定的一批牌、几千局）重新测量，发现并不是：

| 模型 | 累计训练样本 | 对规则 AI（每局升级数） | 每局胜率 |
|---|---|---|---|
| v1.1 随包模型 | 0.55 亿 | +0.53 ± 0.05 | 60.7% |
| 继续训练 | 1.06 亿 | +0.51 ± 0.05 | 60.2% |
| **再练 2 小时（v1.3 随包）** | **3.14 亿** | **+1.19 ± 0.04** | **71.5%** |

（1000 副牌、2000 局复式对局；新模型直接对 v1.1 随包模型 +0.82 级/局，胜率 65%。）

以前的评估每次只打 400 局普通对局，误差有 ±0.2 级/局，正好把这种逐步的进步淹没了；而 0.55 亿到 1.06 亿之间只练了半小时，本来也看不出差别。纯自对弈 DMC 只要继续训练就会继续变强。

为了理解训练的难点，我们还做了几组测量：

| 测量 | 结果 | 说明 |
|---|---|---|
| 同一副牌、交换座位后，0 号队两次结果的相关系数 | 网络 vs 规则 AI 0.10；两个网络之间 0.30 | 牌好牌坏只决定一小部分输赢，打法影响极大，局势对每一步出牌都很敏感 |
| 自对弈时随机探索（ε=0.02）造成的结果方差 | 约占总方差 30% | 一步随机出牌就能改变整局结果，训练目标噪声大，需要大量样本 |
| 能看到四家手牌的“完全信息价值网络”比普通价值网络多解释的方差 | 约 7% | 即使知道所有手牌，结果也很难预测，用它做基线降噪收益很小，没有采用 |

## 对手池训练（可选，默认关闭）

`--league 0.5` 会让一半对局的对手由早先版本的模型来打（基准模型、`--pool` 指定的模型和本次训练的快照），只用最新模型自己的出牌做样本，想法是避免网络只学会“打自己”。

2+2 小时的对比实验（RTX 3060 笔记本，都从 1.06 亿样本的模型出发，2000 副牌复式评估）：

| 训练 2 小时 | 样本数 | 对规则 AI | 对起点模型 |
|---|---|---|---|
| 纯自对弈（ε=0.02） | 2.08 亿 | **+1.18**，胜率 71.9% | **+0.83** |
| 对手池（ε=0.01） | 1.12 亿 | +0.84，胜率 65.4% | +0.50 |

两者直接对打，纯自对弈每局多赢 0.34 级。对手池每一步要多跑一个网络、一半对局只有两个座位产生样本，同样时间里样本只有一半，这个代价超过了它的好处。因此默认仍是纯自对弈。

## 推演搜索（AI 深度思考）

对战时默认开启**推演搜索**（`python/guandan/search.py`），整个过程不使用任何人工规则：

1. 网络给所有合法出牌打分，取最好的 5 手作为候选。
2. 根据当前玩家能看到的信息（已出的牌、每家剩余张数、进贡还贡记录）随机推测另外三家的手牌，采样 24 个“可能的世界”（Rust 实现，`Game::determinize`）。
3. 在每个世界里打出候选牌，然后四家都由网络接着往下打 14 步，再用网络估计局面价值（若本局已结束就用真实结果）。所有世界、所有候选一起批量推理。
4. 取各候选在所有世界里的平均结果，最高的就是 AI 的出牌。

实测（1.06 亿样本的模型对规则 AI，同一批 320 副牌、640 局复式对局）：

| 出牌方式 | 每局升级数 | 每局胜率 |
|---|---|---|
| 只用网络 | +0.50 ± 0.08 | 61.1% |
| 搜索，12 个世界 | +0.71 ± 0.08 | 64.1% |
| **搜索，24 个世界（默认）** | **+0.93 ± 0.08** | **68.8%** |
| 搜索，12 个世界，推演 30 步 | 约 +0.7（256 副牌） | 63% |
| 搜索，推演时网络随机出牌 | +0.36 ± 0.09 | 57.7% |

世界数越多越好，推演更深没有帮助，推演时随机出牌反而更差。CPU 上每步约 0.3～0.6 秒。

**没有采用的尝试：按出牌推断手牌。** 让网络评估“在这个推测的世界里，对手刚才那几手牌出得有多合理”，按这个概率给世界加权。自对弈时这样推测出的手牌和真实手牌的重合度从 51% 提高到 58%，但对规则 AI 反而明显变差：规则 AI 的打法和网络不同（例如从不压队友），用网络的眼光去解读它的出牌会推错。默认关闭（`SearchAgent(belief=...)`）。

搜索前后的对比可以用命令行测：`python -m guandan.evaluate model.pt --opponent rule --search 5,24,14`。

### 实验：搜索标注训练（专家迭代）

`--search-actors N` 会额外启动 N 个进程：它们用推演搜索打牌，并把每个决策里网络前几名候选的**搜索值**（多个可能世界里推演结果的平均）作为训练目标，与普通样本按 `--search-share` 的比例混合训练。搜索值比单局结果的噪声小得多，而且正好覆盖网络最需要区分的那几手。这个选项默认关闭，效果还在评估中。

## 评估：怎样看胜率曲线

训练中会定期把最新模型拿出来，用**复式对局**和三个对手比较：每副牌打两遍，第二遍双方交换座位，牌运基本抵消；每次评估都用同一批牌，前后两次评估的差别就是模型本身的变化。

- **对规则 AI**：一个手写的简单策略（先出小牌、不拆炸弹、不压队友、对手快出完时才炸）。它从不参与训练，只作为一把固定的尺子。
- **对基准模型**：如果选了基准模型，比较新模型是否超过了它。
- **对随机出牌**：最早期的进展。

胜率按局计算：头游在哪一方，哪一方赢下这一局。另一条曲线是平均每局升级数（赢 +1/+2/+3，输则为负），比单纯胜率更能体现“打得漂不漂亮”，评估记录里同时给出它的标准误（±）。

## 推荐参数

参数默认都是“自动”，一般不用改：

| 机器 | 自对弈 | 每进程对局 | 批大小 | 说明 |
|---|---|---|---|---|
| 有 NVIDIA 显卡 | GPU，3 个进程 | 256 | 2048 | 自对弈和学习都在显卡上；RTX 3060 笔记本实测单个 GPU 自对弈进程约 3 万次决策/秒 |
| 只有 CPU | CPU，线程数减 2～4 个进程 | 64 | 512 | 每个进程单线程；选 small 或 medium |

- 有显卡时，自对弈也放在 GPU 上：每个进程同时跑 256 局，一次前向给所有对局打分，比 CPU 多进程快得多，也不会和学习进程抢 CPU。
- 训练中心的日志里 `learner=xx%` 表示学习进程的忙碌程度：接近 100% 说明学习跟不上（可减少自对弈进程），很低说明瓶颈在自对弈（可增加进程数或每进程对局数）。
- 训练可以随时停止。用**同一个名称**再次开始就会从上次的进度继续（包括优化器状态）。
- 一般几百万样本后就能稳定战胜规则 AI；样本越多越强（随包模型训练了 3 亿多样本、约 3 小时），建议至少训练几个小时。

## 命令行训练

```bash
python -m guandan.train --name main --preset medium        # 其余参数自动选择
# 从已有模型继续：
python -m guandan.train --name finetune --base path/to/model.pt
# 对手池（实验，默认关闭），再加几个老模型（用分号分隔）：
python -m guandan.train --name league --base new.pt --league 0.5 --pool "old1.pt;old2.pt"
# 停止：在 guandan_data/runs/<name>/ 下创建名为 STOP 的空文件，或按 Ctrl+C
```

评估两个模型：

```bash
python -m guandan.evaluate guandan_data/runs/main/model.pt --opponent rule --deals 1000
python -m guandan.evaluate new.pt --opponent old.pt --deals 1000
python -m guandan.evaluate new.pt --opponent rule --search 5,24,14 --deals 300   # 开启推演搜索
```

## 训练产物

`guandan_data/runs/<name>/` 下：

- `ckpt_latest.pt`：完整检查点（含优化器，用于继续训练）
- `model.pt`：最新模型（fp16，用于对战）
- `model_<样本数>k.pt`：每小时保存一次的快照
- `metrics.jsonl`：训练与评估记录（训练中心的曲线就来自这里）
- `train.log`：训练日志
